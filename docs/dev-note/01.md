Câu hỏi để chọn

Hỏi: "Game có cần vòng lặp chạy kể cả khi người chơi không bấm gì không?"

Không (Cờ caro, memory, quiz): dùng HTML/React. Code đơn giản, dễ đọc, có accessibility.
Có (rắn, flappy bird, arkanoid): dùng canvas. Nếu game lớn hơn, cân nhắc Phaser hoặc Unity.







Với một website game, back không nhất thiết phải là máy chủ. Có thể tách thành ba phần:

UI (React): hiển thị trạng thái và bắt thao tác của người chơi.
Core (logic): các hàm JavaScript thuần, giữ luật chơi. Đây là phần "back" của game, và nó vẫn chạy trong trình duyệt.
Server (tùy chọn): chỉ cần khi chơi online, lưu điểm, đăng nhập. Bạn sẽ thêm phần này sau.



Front: người chơi chọn quân và ô đích
  → gọi makeMove(state, from, to)          (core)
  → core kiểm tra luật, trả về state mới
  → front render lại state mới






  Core không biết gì về React:

js
// src/games/chess/logic.js
export function makeMove(state, from, to) {
  if (!isLegalMove(state, from, to)) {
    return state // sai luật: giữ nguyên trạng thái
  }
  return {
    ...state,
    board: applyMove(state.board, from, to),
    turn: state.turn === 'white' ? 'black' : 'white',
  }
}

Front chỉ lo giao diện:

jsx
const [state, setState] = useState(initialState)
const [selected, setSelected] = useState(null) // trạng thái giao diện

function handleSquareClick(row, col) {
  if (selected) {
    setState(prev => makeMove(prev, selected, { row, col }))
    setSelected(null)
  } else {
    setSelected({ row, col })
  }
}

Có một điểm quan trọng: state không cùng loại.

state (bàn cờ, lượt đi) là state của game. Thuộc về core.
selected, quân đang hover, trạng thái đang chạy hoạt ảnh là state của giao diện. Thuộc về front.




Vì core không phụ thuộc React, bạn có thể kiểm tra luật cờ vua mà không cần vẽ gì. Đây là lợi ích lớn nhất của cách tách này khi học.
